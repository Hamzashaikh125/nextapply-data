# Data Repo Update — 2 November 2026

## 1. Expiry sync (38 records)
38 opportunities whose deadlines had passed (the **29 October – 1 November**
batch, all dated 1 November in Europe/London) were still `status: published`.
All 38 were flipped to `status: expired`, `isOpen: false`, `expiredAt` set, and
removed from `index.json` (both planes). Published count: **535 → 497**.

The predicate is now canonical **day granularity in Europe/London**: a fixed
deadline expires only once the London civil day containing it has ended. This
keeps a 23:59 London deadline live for the whole local day instead of expiring
it at the UTC instant.

`rolling` and `custom` records were deliberately preserved — they require a
manual/evidence review rather than automatic expiry. The 39th 1 November record
(`university-of-otago-doctoral-scholarship-2026-27`, `deadlineType: custom`) is
therefore still published pending the review in section 5.

## 2. Automated expiry script
Added `scripts/expire-past-deadlines.mjs`:
- **Idempotent** — already-expired records are skipped; repeated runs are safe.
- **Dry-run by default**; pass `--apply` to write. `--now=<ISO>` pins the
  evaluation instant and `--utc` switches to the literal instant predicate.
- Applies the Europe/London day-granularity predicate to fixed deadlines only
  (`rolling` / `open_until_filled` / `custom` never expire automatically).
- Rebuilds `index.json` (published-only, order preserved), `all-slugs.json`
  (all opportunity slugs, sorted) and `stats.json` (total/open/articles/orgs)
  in both planes.
- Ends with a byte-level `data/` → `public/data/` drift report. This run:
  **0 missing twins, 0 differing files**.

## 3. Daily auto-expire workflow
Added and enabled `.github/workflows/auto-expire.yml`:
- Runs daily at **03:00 UTC** (plus `workflow_dispatch`, with an optional
  dry-run input).
- Runs the expiry script with `--apply`, commits with the **`[skip ci]`**
  marker, and pushes.
- Purges every changed `public/data/**` file on jsDelivr.
- Calls the site `data-sync` webhook in batches of 50 with `changedSlugs`
  derived from `public/data/opportunities/<slug>.json`, so detail/checklist
  pages revalidate on demand.
- Because the push uses `GITHUB_TOKEN` (which does not trigger other
  workflows), the purge + webhook are performed inside this workflow itself.
  It uses the same `DATA_SYNC_WEBHOOK_TOKEN` secret and optional `SITE_URL`
  variable as `purge-cache.yml`.
